## Context

At Xpanxion (now UST Global) I designed and built the full UI of Scope Retail's order management system, a greenfield Angular application for orders, inventory, the product catalogue, users and reporting. I also designed and built its sign-in and session management end to end: the Angular side, and the token endpoints in the existing backend.

## How I approached it

<Steps
  label="Approach"
  steps={[
    { title: 'Stop relying on cookies', detail: 'Server-session cookies didn\'t work cleanly across the separate API domain, so every API call carries a JWT instead.' },
    { title: 'Renew before expiry', detail: 'A timer renews the token shortly before it runs out, so nobody is signed out partway through a shift.' },
    { title: 'Check on the server, not only in the browser', detail: 'Route guards decide which screens a role can open, and every API checks the token and the role again. The server can revoke a token early.' },
    { title: 'Keep injected script off the page', detail: 'The token sits in localStorage, so the app relies on Angular\'s built-in sanitising without bypassing it, and is served only over HTTPS with a Content Security Policy.' },
  ]}
/>

<Callout kind="tradeoff">
A JWT in localStorage survives a reload, but any script that runs on the page can read it. So the protection rests on keeping script off the page and on the server being able to revoke a stolen token. Today I'd hand issuing, renewing and revoking tokens to an identity provider.
</Callout>

## Results

- Operations staff stayed signed in through a working shift, with no surprise sign-outs.
- The design passed security review.
- Sign-in and role checks lived in one place, so new screens reused them instead of writing their own.
- Fewer sign-in and access issues were reported.
