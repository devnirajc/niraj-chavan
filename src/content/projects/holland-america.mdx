Holland America Line is a cruise line in the Carnival Corporation & plc group, and hollandamerica.com is its e-commerce site, where travellers browse voyages and destinations, search for a cruise and book it. I worked on the site's front end as a Senior UI Engineer at Xpanxion. My work had three parts: making a photo-heavy site fast, building the cruise search and booking screens, and raising the standard of the front-end code through reusable components, unit tests, code review and mentoring. This was client work, so there is no public repository.

- **Client:** Holland America Line, cruise travel
- **Product:** the cruise booking site, from browsing destinations to completing a booking
- **Users:** travellers researching and booking cruises, on desktop and mobile
- **My role:** Senior UI Engineer at Xpanxion. I built cruise search and booking UI, worked on performance, built shared components, wrote unit tests, reviewed code and mentored developers
- **When:** between 2017 and 2019, during my time at Xpanxion

## The business problem

The site is built around large destination photography, and it had performance problems. The work that fixed them shows what the causes were:

- Pages loaded JavaScript they didn't need.
- Images were heavier than they had to be.
- JavaScript and CSS bundles had grown large.
- Components re-rendered more often than necessary.

On a booking site, each of those slows the path from browsing a voyage to booking it.

## Key technical challenges

### Making a photo-heavy site fast

**Challenge.** Pages shipped more code and image weight than they needed, and did more rendering work than they needed to.

**Solution.** I worked through it in four parts:

- **Lazy loading and code splitting**, so each page loads only the code it needs.
- **Image optimisation** for the large photographs the pages are built around.
- **Smaller bundles and assets**, cutting the JavaScript and CSS each page ships.
- **Less rendering work**, removing unnecessary re-renders so pages stay responsive while people use them.

### Cruise search and booking screens

**Challenge.** Search and booking are the screens where a traveller turns into a customer, and they have to work on every device and browser the audience uses.

**Solution.** I built UI for cruise search and the booking flow, with responsive layouts that stay consistent across devices and browsers.

### One set of components for the whole team

**Challenge.** Several developers were building features on the same site, so the same patterns were needed in many places.

**Solution.** I built reusable components that other developers on the team built their features on.

## Performance

The four parts of the performance work are described under *Making a photo-heavy site fast* above.

## Accessibility

I did accessibility work to WCAG across the pages I worked on, alongside making layouts responsive and consistent across devices and browsers.

## Leadership and collaboration

I built reusable components that other developers on the team used in their features, wrote unit tests for the UI, reviewed other developers' code and mentored them.

## Outcome summary

- **Key achievements:** faster pages through lazy loading, code splitting, image optimisation, smaller bundles and less re-rendering; cruise search and booking UI; reusable components used across the team.
- **Business benefit:** faster pages on the path from browsing a cruise to booking it, with layouts that work across devices and browsers.
- **Long-term value:** shared components and unit tests that other developers built on, backed by code review and mentoring.
